# LLM 비용 및 토큰 설계

수정일: 2026-10-22. 후보 선별·바이트 제한 근거 추출·추출 캐시는 로컬 CLI에 구현했다. 아래 모델 토큰 예산·분석 결과 캐시·평가 계획은 제안이며 실제 LLM 측정 결과가 아니다.

## 1. 가장 중요한 절약 방식

**수집·검사는 코드로 하고, 변경된 문제 해결 건의 구조화 분석을 저장해 여러 기간에서 재사용한다.**

기간별 원본을 매번 통째로 요약하는 방식은 사용하지 않는다. 6개월 결과를 요청해도 6개월 전체 diff를 다시 분석하지 않는다.

처리 계층:

1. 원본과 관계: 필요할 때 근거를 다시 확인할 수 있는 기록.
2. 근거 패킷: 해당 작업에 필요한 발췌와 위치, 데이터 완전성.
3. 작업별 구조화 분석: 문제·제약·실제 대안·구현·검증·기여·누락.
4. 기간별 결과: 조건에 맞는 분석을 골라 한 문장 성과로 표현한 버전.

월간 결과는 주간 문장의 재요약이 아니다. 3개월 결과도 월간 문장만 입력하지 않는다. 같은 구조화 분석을 직접 조회하고, 의심스러운 주장만 원본 근거로 돌아간다.

## 2. LLM 이전에 처리할 일

- 소유자·공급자 인스턴스·저장소·원본 종류·외부 ID/Git OID와 명시적 이슈/PR 연결 기반 중복 제거와 묶기. 공급자가 다르다는 이유로 LLM 분석 경로를 복제하지 않는다.
- 사용자 기여, 저장소, 기간, 완료 상태에 따른 후보 선택.
- 생성 코드·lockfile·이진 파일·반복 문구·인용된 중복 댓글 축소.
- 사용자 override가 가능한 낮은 우선순위 분류.
- 문제 설명·선택 이유·실패 재현·테스트 결과가 있는 발췌 우선 선택.
- 발췌 안에서 기술적 식별자·오류 메시지·실험 조건은 보존.
- 토큰 상한에 맞추어 선택하고 제외한 근거 ID·제외 이유·완전성을 기록.

변경 줄 수가 크다는 이유만으로 성과 순위를 높이지 않는다. 단순 변경 제외만으로 목표를 달성하려 하지 않고, 작은 변경의 영향도도 검토한다.

현재 `evidence`는 선택한 그룹/명시적 커밋 묶음에서 메시지·첫 부모 patch를 읽는다. 기본 본문 합계 64 KiB, 파일당 16 KiB, 최대 20파일, 메시지당 4 KiB를 적용하며 UTF-8의 완전한 줄로 제한한다. 원본 위치·hunk 헤더·생략 사유·불완전 상태를 남기고 lockfile/생성 경로는 명시적 옵션으로 포함할 수 있다. 이 값은 토큰 수나 전체 JSON/요청 크기가 아니며, 모델 연결 시 실제 tokenizer로 지시문·스키마를 포함한 상한을 별도 적용해야 한다.

연관성이 모호한 후보는 작은 메타데이터 집합만 LLM에 제시해 연결을 제안받을 수 있다. 자동 확정하지 않고 추가 호출로 계량한다.

## 3. 호출 단계

### A. 작업별 분석

변경되었으며 선별을 통과한 건에만 호출한다. 결과는 JSON Schema 기반으로 다음 필드를 갖는다.

- `problem`, `constraints`, `alternatives`, `decision`, `implementation`.
- `results`, `verification`, `contribution`.
- `claims`: 주장 텍스트, `evidence_ids`, 사실 상태, 검증 한계.
- `missing_questions`, `completeness`.

없는 대안·수치·결과는 null 또는 빈 배열로 표현한다. 동일 응답에서 질문도 생성해 별도 질문 생성 호출을 줄인다.

### B. 기간별 문장 생성

코드에서 필터링·중복 제거·대표 후보 선별 후 구조화 분석만 전달한다. 문장마다 사용한 주장 ID를 돌려받는다. 검토 UI에서 후보를 수동 변경할 수 있다.

형식·길이·ID 참조·근거 존재·수치 출처는 코드로 검사한다. 이 검사는 출처가 주장을 의미적으로 지지하는지 완전히 보장하지 않는다. 표본 평가와 사용자 검토를 유지한다.

한 줄의 줄바꿈 제거처럼 의미를 바꾸지 않는 수정은 코드로 처리한다. 의미나 사실 검증이 실패하면 좁은 수정 요청을 1회 허용하고, 계속 실패하면 `needs_input`으로 돌린다.

### C. 선택적 추가 분석

근거가 실제로 있는데 작은 모델이 해석하지 못하거나 대안 관계가 복잡할 때만 추가 발췌 또는 상위 모델을 사용한다. 근거 자체가 없는 경우 모델을 키워도 해결되지 않으므로 사용자 질문으로 전환한다.

기본 경로에 다중 에이전트, 별도 비평 모델, 무제한 자기 수정 루프를 넣지 않는다.

## 4. 초기 입력·출력 예산

다음은 조절 가능한 실험 시작값이다. 실제 공급자의 tokenizer로 전체 요청을 계산하고 언어별 글자 수로 대체하지 않는다.

- 작업 분석 입력: 공통 지시·스키마를 포함해 목표 3,000 tokens, 일반 경로 상한 8,000 tokens.
- 작업 분석 출력: 일반 경로 최대 1,000 tokens. 부족한 작업을 조용히 잘라 성공 처리하지 않는다.
- 기간 생성 입력: 목표 4,000 tokens, 일반 경로 상한 8,000 tokens.
- 기간 생성 출력: 최대 1,200 tokens. 기본 대표 성과 3~5개와 주장 참조를 출력한다.
- 선택적 모델 격상: 작업별 최대 1회. 원본 추가 조회와 재분석에도 별도 누적 예산을 둔다.
- 형식·내용 수정: 단계별 최대 1회. 네트워크 재시도와 합쳐 실행 전체의 시도·비용 상한을 적용한다.

상한을 넘으면 우선순위가 낮은 근거를 제외하거나 명시적 하위 작업으로 나눈다. 분할 분석은 변경된 하위 단위만 재실행하고, 최종 결합에서도 원본 근거 ID를 보존한다. 제외가 판단에 영향을 주면 불완전 상태로 남긴다.

사용자별 일일·월간 금액 한도와 요청별 한도를 둔다. 병렬 호출 전 예상 최대비용을 예약하고 실제 사용량으로 정산해 동시 실행의 예산 초과를 줄인다.

## 5. 캐시와 무효화

### 구현된 로컬 근거 추출 캐시

`.cache/evidence`의 추출 캐시는 patch 읽기를 재사용하며 LLM 결과 캐시와 구분한다. 로컬 Git 공통 디렉터리 범위, 선택 커밋과 실제 파일 manifest, Git 버전·설정/유효 속성 hash, 기여 분류·규칙 버전, 경로 범위·명시적 묶기·바이트/파일 수 한도가 키를 결정한다. 실행/관측 시각·출력 경로·기간은 제외한다. 별도 `contentVersion`은 정규화한 패킷의 SHA-256이다.

캐시 hit에도 커밋 메타데이터·도달 가능성·manifest·blob 존재를 확인한다. 조회 실패·객체 누락은 캐시하지 않고, 손상된 캐시는 재추출한다. 예산·이진 파일 등 결정적인 생략이 있는 패킷은 불완전 표시와 함께 재사용할 수 있다. 다른 clone은 별도 범위이고, Git 설정 원문은 저장하지 않는다. 다중 사용자 권한 검증·모델 결과·프롬프트 캐시는 아직 구현하지 않았다.

### 앱 결과 캐시: 호출 자체를 없애기

완료한 분석·문장 결과를 PostgreSQL에 저장한다. 동일 입력과 설정이면 공급자를 다시 호출하지 않는다.

분석 key 구성:

```text
SHA256(canonical_json({
  owner_id, repository_scope, connection_scope, capabilities_version, work_item_id,
  evidence_ids_and_version_hashes,
  source_completeness, contribution_mapping_version,
  extraction_version, grouping_version, filter_version,
  user_confirmation_version,
  prompt_version, schema_version,
  provider, model_revision_or_epoch, generation_settings
}))
```

기간 결과 key 구성:

```text
SHA256(canonical_json({
  owner_id, resolved_start_at, resolved_end_at, timezone,
  selected_analysis_ids_and_versions,
  ranking_version, user_selection_version,
  target_role, language, tone, max_items,
  prompt_version, schema_version,
  provider, model_revision_or_epoch, generation_settings
}))
```

- 참조 ID를 정렬하고 canonical serialization을 사용한다.
- `updated_at`만 바뀌고 실제 분석 입력이 같으면 재사용한다.
- 연결 근거·본문·리뷰·기여자 매핑·사용자 확인이 바뀌면 영향받는 작업과 해당 기간 결과만 무효화한다.
- 필터가 다시 포함한 작업, 작업 병합·분리, 삭제된 근거도 무효화에 반영한다.
- 모델 alias가 실제 버전을 숨기면 앱의 모델 epoch를 명시적으로 올려 관리한다.
- `지금부터 한 달` 같은 상대 문자열을 key로 사용하지 않는다. 고정한 절대 범위를 사용한다.
- 새 요청에서도 접근 권한을 다시 검사한다. 캐시 hit가 권한 검사를 우회하지 않는다.
- 사용자 편집본은 생성 캐시와 별도 버전으로 보존한다.
- 실패·거부·불완전 출력은 정상 결과 캐시에 저장하지 않는다. 불완전 원본으로 만든 초안은 완전성 표시를 보존한다.

### 공급자 프롬프트 캐시: 남은 호출 비용 줄이기

공통 지시와 출력 스키마는 앞부분에 고정하고, 변경되는 근거와 요청 값은 뒤에 둔다. 모델별 최소 길이·캐시 경계·유지 조건을 확인하고 실제 cache hit를 측정한다. 공통 prefix만 같다고 항상 캐시되는 것으로 가정하지 않는다.

공급자 캐시는 새 응답을 생성하므로 출력 비용과 호출은 남는다. 앱 결과 캐시와 구분한다. 토큰 절약량과 할인에 의한 비용 절약량도 따로 측정한다. 캐시를 맞추기 위한 불필요한 원문 추가는 기본 정책으로 사용하지 않는다.

근거: [OpenAI Prompt caching](https://developers.openai.com/api/docs/guides/prompt-caching). 구체적인 지원 조건은 모델 선택 시 재확인한다.

## 6. 모델 선택

모델명보다 평가 절차를 먼저 고정한다.

1. 실제 사용 권한이 있는 자료 또는 정제된 공개 표본으로 기준 세트를 만든다.
2. 작은 모델 하나로 구조화 추출·한국어 문장화·근거 준수 품질을 평가한다.
3. 실패 유형이 근거 누락이면 수집·질문을 개선하고, 해석 실패이면 프롬프트·모델 후보를 비교한다.
4. 고성능 후보와 비교해 승인된 성과 문장당 비용과 처리 시간을 측정한다.
5. 기준을 통과한 최소비용 모델을 선택하고 실제 모델 버전·설정을 기록한다.

JSON Schema 준수는 사실 정확성의 보장이 아니다. [OpenAI 구조화 출력 문서](https://developers.openai.com/api/docs/guides/structured-outputs)도 내용상 오류 가능성을 명시한다.

대량의 최초 과거 이력 분석은 즉시 결과가 필요하지 않다면 공급자 batch 처리를 나중에 검토한다. 초기에는 큐 기반 일반 호출로 재시도·비용·품질을 먼저 검증한다.

## 7. 비용·속도 측정

각 호출에서 기록할 항목:

- 단계, 소유자, 작업 ID, 모델과 설정.
- 공급자 보고 입력 토큰, cached input 토큰, 출력 토큰, 제공되는 추론 토큰.
- 실제 결제 체계에 맞춘 비용, 요청 시각, 응답 지연, 재시도와 오류.
- 앱 결과 캐시 hit와 무효화 사유.
- 필터 전후 후보 수, 원문/선별 입력 토큰, 수집 불완전성.

비용은 공급자별 meter의 정의를 확인해 계산한다. 일반적인 입력·출력 과금의 예시는 다음과 같다.

```text
call_cost = uncached_input_tokens × uncached_input_rate
          + cached_input_tokens × cached_input_rate
          + billed_output_tokens × output_rate
          + other_provider_specific_charges
```

요율은 과금 단위에 맞추고 버전·적용일을 보관한다. 공급자가 보고하는 총 입력에 cached tokens가 포함되면 차감 후 계산한다. 추론 토큰이 출력 토큰에 이미 포함되어 있으면 중복 합산하지 않는다.

비교할 시나리오:

1. 최초 수집·최초 분석.
2. 변경 없는 동일 기간 재요청: LLM 호출 0회가 목표다.
3. 1개월 결과 후 3개월 결과 요청: 기존 분석은 재사용하고 새 범위의 미분석 작업과 새 결과 생성만 처리한다.
4. 작업 하나의 근거 변경: 관련 분석과 이를 포함한 결과만 재생성한다.
5. 저장소 대량 초기화, 큰 PR, API 제한 및 일시 오류.

지표는 총 토큰·총비용·승인 문장당 비용·p50/p95 생성 지연·수집 지연·캐시 재사용률·사용자 수정률·근거 없는 주장률이다. 캐시 결과 조회 시간과 최초 생성 시간은 구분한다.

절감률은 동일한 표본·출력 품질·기간 요청 시나리오에서 기준 방식과 비교한 뒤 보고한다. 출력 토큰·추론·재시도·사용자 수정 비용을 빼놓고 입력 토큰만으로 전체 비용 절감을 주장하지 않는다.
